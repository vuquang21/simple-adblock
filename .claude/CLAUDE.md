# Simple AdBlock

## Rules

- Always answer in Vietnamese.

A Chrome Manifest V3 extension that blocks ads via domain blocklists. It auto-detects
ad-like third-party requests and offers a dashboard to import lists and add/remove domains.
Network blocking and element hiding are both per-site overridable via a whitelist.

## Architecture

- **`manifest.json`** — MV3 config. Uses `declarativeNetRequest` (blocking + whitelist allow
  rules + the matched-rule count), `declarativeNetRequestFeedback` (needed by
  `getMatchedRules`, unpacked only), `webRequest` (observing requests for auto-detection),
  `scripting` (injecting the content scripts into a tab that was already open when the extension
  was reloaded, so a pick works without a reload), and `storage`. Pins `minimum_chrome_version` 121 for the 30k safe-dynamic-rule limit. Loads
  `youtube-main.js` as a static `world: "MAIN"` content script for `*://*.youtube.com/*`.
  The isolated-world content script runs `shared.js`, `cosmetic-rules.js`, `cosmetic.js` and
  `picker.js` in that order, because `picker.js` calls `addHiddenRule()` from `cosmetic.js`.
- **`background.js`** — service worker. Rebuilds dynamic DNR rules from the blocklist and the
  whitelist, auto-blocks ad-like third-party requests it observes, and keeps the per-tab block
  count in the action badge. Request writes are batched (2s flush).
- **`shared.js`** — helpers shared by dashboard/popup/content script, loaded via
  `importScripts` in the worker and `<script>`/content script in pages: `parseDomains`,
  `parseCosmetic`, `parseScopedCosmetic`, `siteRulesFor`, `mergeSiteRules`, `MAX_SITE_RULES`,
  `isWhitelisted`, `WHITELIST_ID_BASE`, `getState`, `setDomains`, `AD_HINT`, `AD_LOOK`,
  `baseDomain`. `AD_LOOK` is the one definition of an ad-looking id/class (`banner-quang-cao`,
  `ads-top`), shared by the picker's container walk and `auto-hide.js`, so "looks like an ad"
  cannot drift between them.
  `parseCosmetic` keeps only generic `##` rules; a site-scoped `example.com##.ad` is
  `parseScopedCosmetic`'s job and is deliberately never applied to the whole web. Every
  selector passes `safeSelector` first, because they all land in one generated stylesheet where
  an unterminated `/*` or quote would swallow the rules after it. `mergeSiteRules` stops at a
  selector count and a byte budget, since storage.local is quota-limited.
- **`default-domains.js`** — hand-curated starter blocklist (`DEFAULT_DOMAINS`).
  `background.js` merges it into `domains` on install/startup, tracked by `seedVersion`, so a
  new batch reaches existing installs too. An existing list is merged, never replaced. Keep
  dual-use infrastructure out. The last group is betting/casino brands (HIT.CLUB, 789WIN,
  SUN88, RIKVIP, WIN79 …): those buy the banner slot instead of serving it, so blocking the
  brand removes the iframe creative and the click-through alike.
- **`cosmetic-rules.js`** — GENERATED by `tools/build-cosmetic.js` from EasyList
  (`node tools/build-cosmetic.js easylist.txt`). `const GENERIC_COSMETIC` — the generic `##`
  selectors that are plain CSS. Do not edit by hand.
- **`cosmetic.js`** — content script, top frame, `document_start`. Injects the shipped generic
  selectors, the user's imported ones and this host's `siteRules` as one hiding stylesheet,
  unless the site is whitelisted. `injectHiding()` keeps a handle on that stylesheet so
  `addHiddenRule()` can hide a picked rule without a reload. On `youtube.com` it also injects
  scoped ad selectors as one rule per selector (a single invalid selector must not drop the
  whole stylesheet), removes feed/watch/sidebar ad nodes (including their grid cell), dismisses
  the anti-adblock enforcement popup, seeks the ad `<video>` once to just before its end at 16x
  + mute, presses Skip, and mirrors the enabled/whitelist state into the `sab-ads-off`
  `localStorage` key that `youtube-main.js` reads on the next load.
- **`picker.js`** — content script, top frame, after `cosmetic.js` in the same isolated world.
  Armed from the popup (`sab-pick` message): a full-viewport overlay takes the clicks (an ad's
  own capture handler must not navigate away mid-pick), a highlight box follows the hovered
  node, and a click stores a rule for this host in `siteRules` and hides it immediately.
  `pickContainer()` walks up to the nearest ad-shaped wrapper — refusing one that covers most
  of the viewport, since a page-level `<main class="has-ads">` would take the article with it —
  and `pickSelector()` prefers a hand-written id, then the tag with its readable classes, then a
  `body >` `:nth-of-type` chain, never a build-generated class (`css-1q2w3e`) that stops matching
  at the next deploy, and never a selector that matched more than one node: no rule beats a rule
  that hides the wrong thing. Rules are stored on the apex (`www.` stripped) so a pick caught on
  `www.example.com` also hides on `example.com`. Escape cancels, and the overlay re-arms itself
  if the page replaced `<body>` under it. Vietnamese streaming sites serve most banners as
  third-party `<iframe>`s, and hiding the box only fixes that page, so `pickFrameHosts()` also
  collects every foreign frame host inside the picked node (the whole banner grid, same-origin
  players excluded, duplicates dropped) and `pickBlockHosts()` adds them to `domains` — one
  click then kills the same banner on every site. The toast names what was blocked and only
  counts hosts that were actually new.
- **`popup.js`** — the toolbar panel. "Pick an element on this page" arms `picker.js` with a
  `sab-pick` message; when no content script answers — every tab already open when the
  extension was installed, reloaded or updated — it injects `shared.js`, `cosmetic-rules.js`,
  `cosmetic.js`, `picker.js` one file at a time (a re-declaration of the ones already there is a
  caught SyntaxError) and retries, instead of failing the pick with "reload the page". That is
  what the `scripting` permission is for.
- **`auto-hide.js`** — content script, top frame, after `picker.js`. The automatic counterpart of
  the picker: a `MutationObserver` (debounced 400ms) plus one pass at load, for banners a site
  builds at runtime that no imported list knows. Two signals: a third-party `<iframe>`/`<object>`
  whose host is `AD_HINT`-shaped or already in `domains` (strong), or an `AD_LOOK` id/class that
  also holds a creative (img/iframe/picture/canvas). Then the guards, which matter more than the
  signals: never `html/body/main/article/nav/header/footer/video/form`, never a box holding
  `video/article/h1/form`, never more than 12 links (a menu), never under 8000px² (a text link),
  never over half the viewport (the page), at most 40 hides per page (a regex storm stops
  itself). Banners are marked `data-sab-auto` and one attribute rule hides them all, so the
  site's class churn cannot outlive it. Off when blocking is off, on a whitelisted site, or when
  the `autoHide` switch in the popup is cleared — a heuristic eventually hurts one page, and
  whitelisting the whole site is too blunt a way to say "not this one".
- **`youtube-main.js`** — static MAIN-world content script for `*://*.youtube.com/*`.
  Deletes `adPlacements`/`playerAds`/`adSlots`/`adSlotLoggingData` from
  `window.ytInitialPlayerResponse` and from `/youtubei/v1/player` fetch/XHR responses, so no
  video ad is ever scheduled. A MAIN-world script cannot read `chrome.storage`, so its
  enabled/whitelist gate is a `localStorage` flag that `cosmetic.js` keeps in sync.
  shortcut: server-stitched (SSAI) and live-stream ads have no separate ad video to seek, so
  they are not removable client-side.
- **`dashboard.{html,js,css}`** — options page: import lists, view/remove domains and whitelisted
  sites, see diagnostics, the auto-detected log, the element-hiding rules and the per-site ones.
  An import feeds all three stores: `domains`, generic `cosmetic` and `siteRules` (capped by
  `MAX_SITE_RULES`, since a full EasyList brings tens of thousands of scoped rules).
- **`popup.{html,js}`** — toolbar popup: on/off toggle, domain count, per-site allow toggle, the
  blocked count for that page and the “Block an element on this page” button that arms
  `picker.js`.
- **`icons/icon-{16,32,48,128}.png`** — the toolbar and store icon, GENERATED by
  `tools/build-icons.js` (a rounded blue tile with a white “no” ring, drawn as a distance test
  and sampled 4×4 per pixel). Do not edit by hand. They are committed because the browser loads
  them as files on disk and a store upload is rejected without a 128px one.
- **`tools/png.js`** — dependency-free PNG encoder (own CRC32, `zlib.deflateSync`). Shared by
  `tools/build-icons.js` and `tools/package.js`, which needs the same CRC32 for the zip
  container.
- **`tools/package.js`** — hand-run packer: `dist/simple-adblock-<version>.zip` for “Load
  unpacked” or a store upload. The file list is *derived* from `manifest.json` plus the
  `importScripts`/`<script src>` references it points at, so a new content script cannot be
  forgotten; a manifest entry naming a file nobody wrote aborts the build instead of shipping a
  broken package. `--store` drops `declarativeNetRequestFeedback`, which Chrome grants to
  unpacked copies only — a published copy keeps the permission and then silently loses
  `getMatchedRules` (both call sites already guard for that).
  `shortcut:` the zip is written by hand, no zip64 and no signing: fine for an extension package
  far under 4 GB, and a `.crx` is not worth producing since Chrome refuses self-signed installs
  on Windows and macOS.

## State (source of truth)

All state lives in `chrome.storage.local`:
- `enabled: bool` — master on/off
- `domains: string[]` — the blocklist (sorted, unique); merged from `default-domains.js` on
  install/startup
- `seedVersion: number` — which batch of `DEFAULT_DOMAINS` the user has. `background.js`
  re-merges defaults only when this is behind `SEED_VERSION`, so a list the user emptied stays
  empty
- `whitelist: string[]` — sites never blocked or modified; each one becomes an `allow` DNR rule
  at priority 2, which outranks the priority 1 block rules
- `cosmetic: string[]` — user-imported element-hiding selectors (the shipped generic ones live in
  `cosmetic-rules.js`, not in storage)
- `siteRules: {host: string[]}` — element-hiding selectors tied to one host: what `picker.js`
  saves and what the site-scoped `example.com##.ad` rules of an imported list become. Applied on
  that host and its subdomains only, never to another site.
- `ruleIds: {"d:host"|"w:host": id}` — stable DNR rule ids; the `w:` ids start at
  `WHITELIST_ID_BASE` (1000000) so block and allow rules can never share an id
- `autoHide: boolean` — the popup's "Hide ad boxes automatically" switch (default true);
  `auto-hide.js` reads it once per page load
- `detected: {host: count}` — log of auto-blocked hosts, display only, capped at top 500
- `lastError: string|null` — last DNR sync failure, shown in the dashboard

`background.js` reacts to `storage.onChanged` to re-sync rules, so UI code only writes storage —
it never touches DNR directly.

## Tests

Plain Node + `assert`, no framework or `package.json`. Run each directly:
```
node test/parse.test.js
node test/background.test.js
node test/cosmetic.test.js
node test/picker.test.js
node test/auto-hide.test.js
node test/youtube-main.test.js
```
`background.test.js` runs `background.js` in a `vm` against a fake `chrome` API;
`cosmetic.test.js` does the same for `cosmetic.js` against a fake DOM; `picker.test.js` drives
`picker.js` (arm → hover → click → save → hide) against a fake DOM with a small
`querySelectorAll` that understands the selector shapes the picker generates;
`auto-hide.test.js` gives `auto-hide.js` a page where every node is named after what it must
prove, so the guards (menu, article, page wrapper, player, tiny link) get as many cases as the
detections do;
`youtube-main.test.js` does the same for `youtube-main.js` against a fake `window` and `fetch`.

## Conventions

- No build step, no dependencies, no bundler — raw files loaded by the browser.
  `tools/build-cosmetic.js` and `tools/build-icons.js` are by-hand generators for data files,
  and `tools/package.js` zips the result; none of them runs during development or install.
- Comments explain *why*; `shortcut:` comments mark known limits and when to upgrade them.
- DNR allows 30,000 "safe" dynamic rules (`block`/`allow` count as safe) since Chrome 121, which
  is why the manifest pins that version. Static `rule_resources` are **not** an option for
  imported lists: static rules are fixed at package time, and the whole point here is that the
  user imports lists at runtime. A static ruleset would only help for a list bundled with the
  extension.

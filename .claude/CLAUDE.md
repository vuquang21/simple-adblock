# Simple AdBlock

## Rules

- Always answer in Vietnamese.

A Chrome Manifest V3 extension that blocks ads via domain blocklists. It auto-detects
ad-like third-party requests and offers a dashboard to import lists and add/remove domains.
Network blocking and element hiding are both per-site overridable via a whitelist.

## Architecture

- **`manifest.json`** — MV3 config. Uses `declarativeNetRequest` (blocking + whitelist allow
  rules + the matched-rule count), `declarativeNetRequestFeedback` (needed by
  `getMatchedRules`, unpacked only), `webRequest` (observing requests for auto-detection),
  and `storage`. Pins `minimum_chrome_version` 121 for the 30k safe-dynamic-rule limit. Loads
  `youtube-main.js` as a static `world: "MAIN"` content script for `*://*.youtube.com/*`.
- **`background.js`** — service worker. Rebuilds dynamic DNR rules from the blocklist and the
  whitelist, auto-blocks ad-like third-party requests it observes, and keeps the per-tab block
  count in the action badge. Request writes are batched (2s flush).
- **`shared.js`** — helpers shared by dashboard/popup/content script, loaded via
  `importScripts` in the worker and `<script>`/content script in pages: `parseDomains`,
  `parseCosmetic`, `isWhitelisted`, `WHITELIST_ID_BASE`, `getState`, `setDomains`, `AD_HINT`,
  `baseDomain`.
- **`default-domains.js`** — hand-curated starter blocklist (`DEFAULT_DOMAINS`).
  `background.js` merges it into `domains` on install/startup, tracked by `seedVersion`, so a
  new batch reaches existing installs too. An existing list is merged, never replaced. Keep
  dual-use infrastructure out.
- **`cosmetic-rules.js`** — GENERATED by `tools/build-cosmetic.js` from EasyList
  (`node tools/build-cosmetic.js easylist.txt`). `const GENERIC_COSMETIC` — the generic `##`
  selectors that are plain CSS. Do not edit by hand.
- **`cosmetic.js`** — content script, top frame, `document_start`. Injects the shipped generic
  selectors plus the user's imported ones as one hiding stylesheet, unless the site is
  whitelisted. On `youtube.com` it also injects scoped ad selectors as one rule per selector
  (a single invalid selector must not drop the whole stylesheet), removes feed/watch/sidebar ad
  nodes (including their grid cell), dismisses the anti-adblock enforcement popup, seeks the ad
  `<video>` once to just before its end at 16x + mute and presses Skip, and mirrors the
  enabled/whitelist state into the `sab-ads-off` `localStorage` key that `youtube-main.js` reads
  on the next load.
- **`youtube-main.js`** — static MAIN-world content script for `*://*.youtube.com/*`.
  Deletes `adPlacements`/`playerAds`/`adSlots`/`adSlotLoggingData` from
  `window.ytInitialPlayerResponse` and from `/youtubei/v1/player` fetch/XHR responses, so no
  video ad is ever scheduled. A MAIN-world script cannot read `chrome.storage`, so its
  enabled/whitelist gate is a `localStorage` flag that `cosmetic.js` keeps in sync.
  shortcut: server-stitched (SSAI) and live-stream ads have no separate ad video to seek, so
  they are not removable client-side.
- **`dashboard.{html,js,css}`** — options page: import lists, view/remove domains and whitelisted
  sites, see diagnostics, the auto-detected log and the element-hiding rules.
- **`popup.{html,js}`** — toolbar popup: on/off toggle, domain count, per-site allow toggle and
  the blocked count for that page.

## State (source of truth)

All state lives in `chrome.storage.local`:
- `enabled: bool` — master on/off
- `domains: string[]` — the blocklist (sorted, unique); merged from `default-domains.js` on
  install/startup
- `seedVersion: number` — which batch of `DEFAULT_DOMAINS` the user has. `background.js`
  re-merges defaults only when this is behind `SEED_VERSION`, so a list the user emptied stays
  empty
- `whitelist: string[]` — sites never blocked or modified; each one becomes an `allow` DNR rule
  at priority 2, which outranks the priority 1 block rules
- `cosmetic: string[]` — user-imported element-hiding selectors (the shipped generic ones live in
  `cosmetic-rules.js`, not in storage)
- `ruleIds: {"d:host"|"w:host": id}` — stable DNR rule ids; the `w:` ids start at
  `WHITELIST_ID_BASE` (1000000) so block and allow rules can never share an id
- `detected: {host: count}` — log of auto-blocked hosts, display only, capped at top 500
- `lastError: string|null` — last DNR sync failure, shown in the dashboard

`background.js` reacts to `storage.onChanged` to re-sync rules, so UI code only writes storage —
it never touches DNR directly.

## Tests

Plain Node + `assert`, no framework or `package.json`. Run each directly:
```
node test/parse.test.js
node test/background.test.js
node test/cosmetic.test.js
node test/youtube-main.test.js
```
`background.test.js` runs `background.js` in a `vm` against a fake `chrome` API;
`cosmetic.test.js` does the same for `cosmetic.js` against a fake DOM;
`youtube-main.test.js` does the same for `youtube-main.js` against a fake `window` and `fetch`.

## Conventions

- No build step, no dependencies, no bundler — raw files loaded by the browser.
  `tools/build-cosmetic.js` is a by-hand generator for one data file, not a build step.
- Comments explain *why*; `shortcut:` comments mark known limits and when to upgrade them.
- DNR allows 30,000 "safe" dynamic rules (`block`/`allow` count as safe) since Chrome 121, which
  is why the manifest pins that version. Static `rule_resources` are **not** an option for
  imported lists: static rules are fixed at package time, and the whole point here is that the
  user imports lists at runtime. A static ruleset would only help for a list bundled with the
  extension.
